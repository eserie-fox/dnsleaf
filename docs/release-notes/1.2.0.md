# dnsleaf 1.2.0 — pending release

This is release preparation, not a publication or live DNS/PVE acceptance claim.

- Workspace precedence is explicit `--workspace` (including `.`), non-empty `DNSLEAF_WORKSPACE`, then
  cwd/ancestors/home. Each base checks sorted immediate children before itself; first complete match
  wins. No recursive search or sibling ambiguity rejection is used.
- Only regular readable `workspace.yaml` and `entries.yaml` identify a complete source directory.
  Partial candidates warn on stderr and search continues. Complete invalid configurations and
  filesystem inspection errors fail without selecting a replacement.
- All workspace-aware commands share selection semantics. Source configuration loads once for
  logging/operations, including apply's optional sync. Help/version/init remain independent.
- Standard QGA Linux/Windows parsing shares the existing VM backend and conservative selectors.
  Windows coverage is synthetic. QGA cannot prove address lifetime, privacy status or reachability;
  `/128` and EUI-64 preferences remain heuristics and unresolved ambiguity preserves remote DNS.
- Raw discovery succeeds or fails once per distinct source in a sync run; the next run refreshes it.
  Address subprocesses have a finite positive `discovery.timeout_seconds` (default 30 seconds).
  Independent entries continue after Guest errors; configured targets remain protected from prune.
- Enabled entries cannot compete for one normalized FQDN + record type. Full-document validation
  precedes entry writes, provider planning and mutation. Independent A/AAAA and disabled entries work.
- CLI presentation and report DTOs have dedicated modules. Managed-state reconciliation takes an
  explicit timestamp and preserves previous input, ownership timestamps and alias/prune safety.
- Doctor distinguishes files, daily-log symlinks, missing targets and disabled file logging without
  probe writes. Discovery failure emits one useful result and exit, with clean JSON stdout.

## Existing deployments

Workspace schema 4, entries schema 2 and managed-state schema 1 are unchanged. Existing dnsleaf
workspaces (including directories such as `~/ddns-config`) require no relocation or reinitialization.
No new operator field is required. Enabled target collisions now fail validation and must be resolved
before syncing. Existing systemd units retain their explicit absolute workspace and Python environment;
there is no mandatory unit refresh solely for discovery. Keep the installing environment available.

A complete backup directly among searched siblings participates in first-match selection. Keep nested
backups or use explicit `--workspace` when a specific workspace is intended.

See [configuration](../configuration.md), [discovery](../discovery.md), and [release gates](../release.md).
Windows Guest enrollment, agent setup, live PVE checks and publication remain separate operator work.
