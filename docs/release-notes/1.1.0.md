# dnsleaf 1.1.0 — pending release

This release prepares the `eserie-fox/dnsleaf` repository and `dnsleaf` distribution for public PyPI.
Publication and PVE acceptance remain separate release gates.

- Unified package/import/CLI/module identity as `dnsleaf`, with version 1.1.0 in `version.py`.
- Adopted setuptools, explicit package discovery/resources, modern MIT metadata, and author eserie-fox.
- Added thin shared CI/build workflow callers, local OIDC publication jobs, and matching Make commands.
- Kept Linux/PVE, Cloudflare, IPv4/IPv6, LXC/VM/local/static entries, and oneshot/timer execution.
- Changed the workspace logging key to `dnsleaf_logging` and workspace schema to 4. Entries retain
  schema 2. YAML overrides now merge over package JSON defaults before validation; unknown fields
  and wrongly typed operational scalars fail clearly. Runtime path resolution remains separate.
- Removed `--sudo`, automatic privilege elevation, parameter reconstruction, and privilege pre-analysis.
  Use root or explicit sudo with an absolute installed entry. Help, version, and writable local config
  operations remain available to non-root users. State writability is checked before remote writes.
- Bound systemd ExecStart to the installing Python environment without dereferencing virtualenv
  symlinks. Added systemd argument escaping and validation of unit names and interval controls.
- Uninstall stops the timer before the service and fails on essential cleanup errors. Default uninstall
  retains configuration, credentials, and state; purge explicitly deletes the guarded workspace.
  Neither form deletes DNS records.
- Fixed normal sync to reject multiple remote records of the same name/type without deleting extras.
- Preserved dry-run, per-family selection, proxy preservation, and managed-only prune semantics.
- Consolidated workspace/configuration documentation and replaced deployment-like fixture identifiers
  with synthetic values. Added configuration and API-error input redaction.

Prior private deployments must be uninstalled separately and configured afresh. No compatibility
packages, old CLI aliases, field aliases, dual schemas, or state migration are supplied.
See [release preparation](../release.md) for publisher settings and remaining acceptance gates.
