# Release Notes: 1.0.1

> Archived pre-rename internal history for `arbor-ddns`. This is not a public dnsleaf release or current installation guidance.

Release date: 2026-04-01

## Highlights

- `--sudo` now fits the intended non-root operator flow better when arbor-ddns is installed from `.venv`, uv-managed, or other Python-managed environments
- sudo re-exec keeps explicit negative flag choices such as `--no-run-sync` and `--no-prune-managed` intact
- CLI argument reconstruction now has clearer support boundaries and fails fast on unsupported parameter shapes instead of silently drifting
- QEMU guest agent parsing now skips partial bad interface data while still rejecting malformed top-level payloads
- Python module fallback usage is unified around `python -m arbor_ddns` for both CLI sudo re-exec and systemd execution fallback

## Operational notes

This is a patch release that tightens operator-facing behavior rather than changing the workspace model:

- workspace schema and command names are unchanged
- the `--sudo` flow is clearer and more predictable for privileged operations
- discovery is more resilient when one VM reports mixed-quality QGA interface data
- docs and tests were updated to match the finalized 1.0.1 behavior

## Packaging and verification

This release keeps the same local-install workflow, with versioned artifacts updated to 1.0.1:

```bash
pip install -e '.[dev]'
python -m build
pip install dist/arbor_ddns-1.0.1-py3-none-any.whl
arbor-ddns --version
```
